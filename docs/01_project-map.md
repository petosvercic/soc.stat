# 01 — Project Map (Foundation-Driven)

## Scope Rule
This map is derived from the binding conceptual foundation and only structures work sequencing. It does not authorize implementation outside the defined phases.

## Phase Plan (1–4, including 2.5 Gold)

### Phase 1 — Foundation
**Goal:** Lock the conceptual constitution: one-sentence product definition, manifesto intent, axioms, guardrails (mantinels), language laws, and reference daily flow.

**Deliverables:**
- Finalized foundation documents and terminology.
- Explicit non-negotiables for language, behavior, and product boundaries.

**STOP/GO checkpoint:**
- **GO only if** all future decisions can be validated against axioms and mantinels, and daily flow 0–9 is stable.
- **STOP if** any requirement pressures explanation, diagnosis, identity scoring, or behavior pressure.

---

### Phase 2 — Core Content
**Goal:** Build the minimum meaning layer: one spectrum, output format, and statement-of-the-day behavior aligned with “today, not identity.”

**Deliverables:**
- One spectrum definition and interaction intent.
- Result naming format (non-diagnostic, non-authoritative).
- Daily statement framing rules.

**STOP/GO checkpoint:**
- **GO only if** content remains observational, optional, and explanation-light.
- **STOP if** wording becomes prescriptive, motivational pressure appears, or system voice becomes authoritative.

---

### Phase 2.5 — Gold System
**Goal:** Introduce curiosity economy as optional depth, never pressure.

**Deliverables:**
- Gold usage intents: deeper look, unblur layer, look-back, extra spectrum.
- Rules that premium/gold never alters truth, social value, or user worth.

**STOP/GO checkpoint:**
- **GO only if** gold is clearly a voluntary one-off look and cannot behave like performance reward.
- **STOP if** gold mechanics incentivize streaks, status, identity hierarchy, or coercive return loops.

---

### Phase 3 — Social Layer
**Goal:** Add friend visibility as a derived view of current inner setting, without forcing verbal explanation.

**Deliverables:**
- Friend-view model constraints (derived, respectful, non-judgmental).
- Visibility boundaries consistent with “today-only” and “system is not authority.”

**STOP/GO checkpoint:**
- **GO only if** social display preserves silence, choice, and non-comparison.
- **STOP if** social features introduce ranking, pressure, or personality permanence.

---

### Phase 4 — Production
**Goal:** Translate locked concepts into implementation artifacts (UI/code later), preserving meaning.

**Deliverables:**
- Build-ready specifications traced to foundation sections.
- Release criteria enforcing language and guardrail compliance.

**STOP/GO checkpoint:**
- **GO only if** every production item maps to a foundation clause and phase ownership.
- **STOP if** implementation convenience requires violating axioms/mantinels.

## Cross-Phase Governance Rule
If an item cannot be clearly assigned to a phase, it is not done.
